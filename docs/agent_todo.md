# 최종 프로세스

## 1단계 목표

1. 소스 결정
    - 추적할 채용 사이트 및 페이지를 등록
    - 초기에는 하드코딩으로 시작하고, 추후 유저별 관리 방식으로 확장 검토

2. 소스 실행 및 공고 링크 수집
    - seed URL에 접속
    - agent-browser CLI 기반으로 수집 진행
    - 현재는 별도 개발 리소스 없이 시작
    - 공고 링크 수집
        - 제목, 회사명, 마감일, 링크 추출
        - 본문은 제외
        - 회사명과 마감일 기준으로 1차 선별 수행

3. 수집 시점 기록
    - 다음 수집 시 현재 시점 이후 등록된 공고만 수집
    - 수집 시점은 회사별 업무시간을 고려해 결정
    - 별도 리소스 없이도 중복 수집을 줄일 수 있는 방향으로 설계

4. 메일 전송
    - 크롤링과 분리된 후속 단계에서 Digest 메일 발송
    - 대상 선정은 저장된 공고와 유저별 조건을 기준으로 별도 처리
    - 형태: 제목/회사/마감일/링크를 텍스트 본문으로 구성
    - 발송 실패 정책은 메일링 프로세스에서 독립적으로 관리

5. 공고 및 추천 이력 저장
    - 간단한 데이터베이스 또는 파일 시스템 구축
    - 추후 분석 및 개선을 위해 저장된 데이터를 활용하도록 설계

## 2단계 목표

1. 본문 읽기
    - 공고 본문까지 수집
    - 본문이 이미지 기반인 경우 대응 방안 검토
    - 제목과 본문 형태로 정제
    - 공고 저장 또는 메일 발송을 위해 임시 저장 처리
    - ADK에서 바로 구조화 출력이 어려운 경우를 고려

2. 적합도 계산
    - AI 기반으로 공고와 사전 입력된 유저 정보를 비교해 적합도 산정

3. 추천 여부 결정
    - 신규 공고인지 판단
    - 이전에 추천한 공고인지 판단
    - 내용이 갱신되었는지 판단
    - 재노출 주기가 지났는지 판단

4. 추천 이력 저장
    - 추천 타입 저장
    - 추천 이유 저장
    - 추천 시점 저장

5. Digest 생성 및 메일링
    - 신규 / 갱신 / 재노출 공고를 묶어 별도 메일링 프로세스에서 Digest 생성 후 발송

## 다음 작업(확정)

1. 크롤링과 메일링 분리 먼저 구현
    - 이유: 이후 유저별 메일링을 지원하려면 수집과 발송의 실행 경계를 먼저 분리해야 함
    - 범위:
        - 크롤러 실행 경로에서 메일러 생성/신규 공고 판별/발송 제거
        - SMTP 설정과 메일러 구현을 별도 메일링 영역으로 이동
        - 크롤러는 공고 저장과 crawl run 기록까지만 수행
    - 완료 기준:
        - SMTP 환경변수 없이도 `cmd/crawler`가 실행 가능함
        - 메일러 코드는 크롤러 패키지 밖으로 분리됨
        - 단위 테스트(크롤러 저장 흐름, 메일러 본문 생성, 목적별 환경변수 검증) 통과
